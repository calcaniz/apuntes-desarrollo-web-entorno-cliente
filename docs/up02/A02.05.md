# A02.05 · Revisión y depuración de FestWeb

Durante esta unidad hemos construido pequeños programas para almacenar datos, realizar cálculos, tomar decisiones y repetir operaciones.

En esta actividad final revisaremos el código de **FestWeb** para mejorar su legibilidad, documentarlo y comprobar su funcionamiento mediante las herramientas de desarrollo del navegador.

## 1. Objetivos

Al finalizar la actividad serás capaz de:

- Revisar y mejorar la legibilidad de un programa.
- Utilizar nombres descriptivos para variables y constantes.
- Aplicar una indentación y un formato coherentes.
- Añadir comentarios útiles sin explicar instrucciones evidentes.
- Interpretar los errores mostrados en la consola.
- Utilizar puntos de interrupción.
- Ejecutar el código paso a paso.
- Examinar el valor de las variables durante la ejecución.
- Identificar y corregir errores sencillos.
- Preparar una versión final del programa.

## 2. Punto de partida

Utilizaremos el programa desarrollado en la actividad anterior:

**A02.04 · Simulación de venta de entradas**

El programa deberá incluir, al menos:

- Los datos del evento.
- La captación del número de entradas.
- La conversión y validación del dato.
- Una estructura condicional.
- Un bucle.
- El cálculo de la recaudación.
- Un resumen final mostrado en la consola.

!!! info "Finalidad de la actividad"

    No añadiremos nuevas funcionalidades importantes. El objetivo es revisar, comprender, documentar y depurar el código existente.

## 3. Preparación del proyecto

1. Abre el proyecto de **FestWeb**.
2. Ejecuta el servidor de desarrollo:

```bash
npm run dev
```

3. Abre la aplicación en el navegador.
4. Abre las herramientas de desarrollo.
5. Accede a la pestaña **Consola**.
6. Comprueba que el programa se ejecuta sin errores.

Añade un comentario para identificar esta revisión:

```js
// A02.05 · Revisión y depuración de FestWeb
```

## 5. Revisión de los nombres

Revisa todas las variables y constantes del programa.

Los nombres deberán:

- Describir claramente el dato almacenado.
- Utilizar la notación `camelCase`.
- Evitar abreviaturas innecesarias.
- Evitar nombres genéricos como `x`, `dato`, `valor` o `cosa`.

Ejemplos:

| Nombre poco descriptivo { .table-full-container .table-content .table-bg-principal .table-cl-secundario } | Nombre recomendado { .table-full-container .table-content .table-bg-principal .table-cl-secundario } |
|---|---|
| `n` | `cantidadEntradas` |
| `p` | `precioEntrada` |
| `total` | `recaudacionTotal` |
| `disponible` | `entradasDisponibles` |
| `max` | `maximoEntradasPorCompra` |

Modifica los nombres que no permitan comprender fácilmente su finalidad.

## 6. Uso de `const` y `let`

Revisa las declaraciones del programa:

- Utiliza `const` cuando la variable no vaya a recibir un nuevo valor.
- Utiliza `let` cuando sea necesario modificar su valor.
- Evita utilizar `var`.
- Declara cada variable cerca del lugar en el que se utiliza.

!!! pregunta "Revisión"

    ¿Hay alguna variable declarada con `let` cuyo valor no cambia durante el programa?

Si la respuesta es afirmativa, sustitúyela por `const`.

## 7. Formato del código

Revisa el formato general:

- Utiliza una indentación coherente.
- Añade espacios alrededor de los operadores.
- Separa mediante líneas en blanco los bloques relacionados.
- Mantén una posición coherente para las llaves.
- Evita líneas excesivamente largas.
- Utiliza punto y coma de manera coherente.

Puedes utilizar el formateador de Visual Studio Code para ordenar automáticamente el documento:

```text
Shift + Alt + F
```

!!! warning "Formatear no es corregir"

    El formateador mejora la presentación del código, pero no soluciona los errores de funcionamiento.

## 8. Comentarios útiles

Añade comentarios para explicar las decisiones que no sean evidentes.

Un comentario útil explica principalmente **por qué** se realiza una operación:

```js
// Limitamos la compra para evitar que una persona reserve todo el aforo.
```

Evita comentarios que solamente repitan la instrucción:

```js
// Sumamos uno.
contador++;
```

Añade comentarios breves para identificar:

1. La declaración de los datos del evento.
2. La captación y validación de la cantidad.
3. El procesamiento de las ventas.
4. El cálculo de la recaudación.
5. La presentación del resumen.

!!! pregunta "Reflexiona"

    ¿Podría comprender el programa otra persona sin que tú tuvieras que explicárselo?

## 9. Mensajes de depuración

Añade temporalmente mensajes para observar el funcionamiento del programa:

```js
console.log("Cantidad recibida:", cantidadIntroducida);
console.log("Cantidad convertida:", cantidadEntradas);
console.log("Entradas vendidas:", entradasVendidas);
console.log("Recaudación acumulada:", recaudacionTotal);
```

Utiliza también `console.error()` cuando se detecte un dato no válido:

```js
console.error("La cantidad introducida no es válida.");
```

Ejecuta el programa y comprueba cómo cambian los valores.

Cuando termines la revisión, elimina los mensajes que ya no sean necesarios.

## 11. Localización de errores

Introduce y corrige, uno por uno, los siguientes errores:

### Error 1. Nombre incorrecto

Modifica el nombre de una variable en una única instrucción.

Comprueba:

- El mensaje mostrado en la consola.
- El número de línea indicado.
- El tipo de error producido.

### Error 2. Conversión eliminada

Elimina temporalmente la conversión con `Number()`.

Introduce el valor `"2"` y observa:

- El tipo del dato.
- El resultado de las operaciones.
- Las comparaciones que dejan de funcionar correctamente.

### Error 3. Contador sin actualización

Elimina temporalmente la actualización del contador de un bucle.

!!! danger "Precaución"

    Esta modificación puede provocar un bucle infinito. Realízala únicamente durante la demostración guiada y detén la ejecución inmediatamente.

### Error 4. Condición incorrecta

Cambia uno de los límites utilizados para validar la cantidad de entradas.

Prueba los valores límite y comprueba qué caso deja de funcionar.

Después de cada prueba, restaura el código correcto.
